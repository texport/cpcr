# Интерактивная база знаний: Протокол передачи данных ККМ -> ОФД (v2.0.3)

Это хранилище (Vault) содержит структурированное, разбитое по модулям описание протокола обмена данными между контрольно-кассовыми машинами (ККМ) и серверами оператора фискальных данных (ОФД).

Документация оптимизирована для отображения в **Obsidian** и в веб-интерфейсе Git (GitHub/GitLab), обеспечивая мгновенную перекрестную навигацию между protobuf-структурами, перечислениями (Enums) и бизнес-процедурами.

---

## 🛠️ Как открыть базу знаний

### Вариант 1: Через Obsidian (Рекомендуется)
1. Установите и запустите приложение [Obsidian](https://obsidian.md/).
2. Нажмите **Open folder as vault** (Открыть папку как хранилище).
3. Выберите папку `protocol/` в данном репозитории.
4. Нажмите `Ctrl+O` (или `Cmd+O` на macOS) и введите `Оглавление`, чтобы открыть интерактивное оглавление.
5. Вы можете включить режим **Graph View** (Интерактивный граф связей), чтобы увидеть, какие типы данных в каких сообщениях используются.

### Вариант 2: Через веб-интерфейс Git / Любой Markdown-редактор
Просто откройте [Оглавление](protocol/Оглавление.md) и переходите по относительным ссылкам. Все ссылки работают нативно во всех современных Git-хостингах.

## 📋 Государственные технические требования к ККМ

В соответствии с законодательством Республики Казахстан, кассовые аппараты делятся на три категории, каждая из которых должна отвечать строгому набору государственных технических требований:

*   📄 **[Раздел 1. ККМ с функцией фиксации и передачи данных](protocol/requirements/Раздел%201.%20Требования%20к%20ККМ%20с%20функцией%20фиксации%20и%20передачи%20данных.md)** — требования к традиционным аппаратным онлайн-ККМ, оснащенным собственной фискальной памятью/накопителем и поддерживающим работу в автономном режиме (до 72 часов).
*   📄 **[Раздел 2. ККМ с функцией передачи данных](protocol/requirements/Раздел%202.%20Требования%20к%20ККМ%20с%20функцией%20передачи%20данных.md)** — требования к кассовым аппаратам без автономной фискальной памяти, которые должны блокировать кассовые операции при временном отсутствии связи с ОФД.
*   📄 **[Раздел 3. Технические требования к АПК ККМ](protocol/requirements/Раздел%203.%20Технические%20требования%20к%20АПК%20ККМ.md)** — требования к аппаратно-программным комплексам (веб-кассы, мобильные приложения, серверные фискальные решения).

## 🎨 Особенности оформления

- 💡 **Подсказки и предупреждения**: Важные логические правила и ограничения работы касс выделены Obsidian-стилем (например, `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]`).
- 🔗 **Интерактивные ссылки**: Любой protobuf-тип внутри таблиц автоматически ссылается на соответствующий markdown-файл с его структурой.
- ⚡ **Никаких битых ссылок**: Полная целостность ссылочных связей подтверждена автоматической валидацией (Broken links: 0).
