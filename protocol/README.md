# Интерактивная база знаний: Протокол передачи данных ККМ -> ОФД (v2.0.3)

Это хранилище (Vault) содержит структурированное, разбитое по модулям описание протокола обмена данными между контрольно-кассовыми машинами (ККМ) и серверами оператора фискальных данных (ОФД).

Документация оптимизирована для отображения в **Obsidian** и в веб-интерфейсе Git (GitHub/GitLab), обеспечивая мгновенную перекрестную навигацию между protobuf-структурами, перечислениями (Enums) и бизнес-процедурами.

---

## 🛠️ Как открыть базу знаний

### Вариант 1: Через Obsidian (Рекомендуется)
1. Установите и запустите приложение [Obsidian](https://obsidian.md/).
2. Нажмите **Open folder as vault** (Открыть папку как хранилище).
3. Выберите папку `protocol/` в данном репозитории.
4. Нажмите `Ctrl+O` (или `Cmd+O` на macOS) и введите `Оглавление`, чтобы открыть интерактивное оглавление.
5. Вы можете включить режим **Graph View** (Интерактивный граф связей), чтобы увидеть, какие типы данных в каких сообщениях используются.

### Вариант 2: Через веб-интерфейс Git / Любой Markdown-редактор
Просто откройте [Оглавление](Оглавление.md) и переходите по относительным ссылкам. Все ссылки работают нативно во всех современных Git-хостингах.

## 📂 Общая структура проекта

Вся база знаний организована аккуратно по папкам в строгом соответствии с оригинальным документом спецификации (без числовых префиксов в именах файлов):

```text
protocol/
├── Оглавление.md                  # Интерактивное оглавление и карта спецификации
├── README.md                      # Настоящее руководство разработчика
├── Общая информация.md            # Вводная часть, Protobuf, Little-endian
├── Приложение.md                  # История версий протокола (Changelog)
│
├── Структура сообщений/            # Транспортный уровень и общий фрейм пакетов
│   ├── Сообщения.md               # HEADER + PAYLOAD
│   ├── Заголовки сообщений.md     # APPCODE, VERSION, SIZE...
│   ├── Коды команд.md             # CommandTypeEnum
│   ├── Коды ответов.md            # ResultTypeEnum
│   ├── Структура запроса.md       # Request
│   └── ...
│
├── Команды/                       # Описание команд бизнес-логики (COMMAND_*)
│   ├── Инициализация/             # COMMAND_INFO
│   ├── Закрытие смены/            # COMMAND_CLOSE_SHIFT (CloseShiftRequest)
│   ├── Обработка чека/            # COMMAND_TICKET (Запрос/Ответ/Товары/Налоги чека)
│   ├── Внесение и снятие денег/   # COMMAND_MONEY_PLACEMENT
│   ├── Отправка и получение отчетов/ # COMMAND_REPORT (ReportRequest, ZXReport)
│   ├── Получение номенклатуры/    # COMMAND_NOMENCLATURE
│   ├── Служебная часть сообщений/ # Системные метаданные (ServiceRequest/Response)
│   └── Авторизация/               # COMMAND_AUTH (AuthRequest/Response)
│
├── Общие типы данных/              # Базовые общие типы и перечисления
│   ├── Дата.md                    # Date
│   ├── Деньги.md                  # Money
│   ├── Виды налогообложений.md    # TaxationTypeEnum
│   ├── Сведения об операторе.md   # Operator
│   ├── Связанное налогообложение/ # BindedTaxation и BindedTax
│   └── ...
│
└── Процедуры установления связи/   # Бизнес-процессы и режимы работы устройства
    ├── Работа в нормальном режиме.md   # ONLINE
    ├── Работа в автономном режиме.md   # OFFLINE (Локальная очередь чеков)
    ├── Работа в режиме блокировки.md    # BLOCKED (Ошибки очереди)
    └── Работа в режиме серверной блокировки.md # SERVER_BLOCKED (Ограничение по ОФД)
```

## 🎨 Особенности оформления

- 💡 **Подсказки и предупреждения**: Важные логические правила и ограничения работы касс выделены Obsidian-стилем (например, `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]`).
- 🔗 **Интерактивные ссылки**: Любой protobuf-тип внутри таблиц автоматически ссылается на соответствующий markdown-файл с его структурой.
- ⚡ **Никаких битых ссылок**: Полная целостность ссылочных связей подтверждена автоматической валидацией (Broken links: 0).
