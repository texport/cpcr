# Команды протокола

В данном разделе приведено описание бизнес-логики и прикладных команд протокола обмена ККМ с ОФД. Обмен сообщениями инициируется устройством ККМ, которое отправляет структурированный запрос, а сервер возвращает ответ с результатом обработки.

Каждому бизнес-процессу соответствует определенный код команды (`CommandTypeEnum`), передаваемый в заголовке транспортного пакета, и соответствующий прикладной блок данных (`payload`) внутри общего protobuf-контейнера.

---

### Список прикладных команд:

* **⚙️ [Инициализация](Инициализация/Инициализация.md) (`COMMAND_INFO`)** — запрос параметров конфигурации кассового аппарата с сервера при старте работы или по запросу оператора.
* **🔑 [Авторизация](Авторизация/Авторизация.md) (`COMMAND_AUTH`)** — аутентификация и авторизация оператора (кассира) на сервере ОФД.
* **🧾 [Обработка чека (Обзор)](Обработка%20чека/Обработка%20чека.md) (`COMMAND_TICKET`)** — ключевая фискальная команда протокола для регистрации чеков (продажа, возврат продажи, покупка, возврат покупки).
  * [Запрос чека](Обработка%20чека/Запрос%20чека.md) (`TicketRequest`)
  * [Ответ на чек](Обработка%20чека/Ответ%20на%20чек.md) (`TicketResponse`)
* **🚪 [Закрытие смены (Обзор)](Закрытие%20смены/Закрытие%20смены.md) (`COMMAND_CLOSE_SHIFT`)** — процедура завершения смены на ККМ, при которой на сервере формируется Z-отчет.
  * [Запрос закрытия смены](Закрытие%20смены/Запрос%20закрытия%20смены.md) (`CloseShiftRequest`)
* **💵 [Внесение и снятие денег (Обзор)](Внесение%20и%20снятие%20денег/Внесение%20и%20снятие%20денег.md) (`COMMAND_MONEY_PLACEMENT`)** — регистрация операций внесения (пополнения) или изъятия (инкассации) наличных средств в денежном ящике кассы.
  * [Запрос внесения-снятия денег](Внесение%20и%20снятие%20денег/Запрос%20внесения-снятия%20денег.md) (`MoneyPlacementRequest`)
* **📊 [Отправка и получение отчетов (Обзор)](Отправка%20и%20получение%20отчетов/Отправка%20и%20получение%20отчетов.md) (`COMMAND_REPORT`)** — отправка промежуточных X-отчетов или передача сменных финансовых итогов (Z-отчетов).
  * [Запрос отчета](Отправка%20и%20получение%20отчетов/Запрос%20отчета.md) (`ReportRequest`)
  * [Ответ сервера с отчетом](Отправка%20и%20получение%20отчетов/Ответ%20сервера%20с%20отчетом.md) (`ReportResponse`)
  * [Основная часть ZX-отчета](Отправка%20и%20получение%20отчетов/ZXReport/Основная%20часть%20ZX-отчета.md) (`ZXReport`)
* **📦 [Получение номенклатуры (Обзор)](Получение%20номенклатуры/Получение%20номенклатуры.md) (`COMMAND_NOMENCLATURE`)** — запрос актуального списка товаров и услуг с сервера ОФД для синхронизации локальной базы ККМ.
  * [Запрос номенклатуры](Получение%20номенклатуры/Запрос%20номенклатуры.md) (`NomenclatureRequest`)
  * [Ответ сервера с номенклатурой](Получение%20номенклатуры/Ответ%20сервера%20с%20номенклатурой.md) (`NomenclatureResponse`)
* **🔄 [Служебный обмен](Служебный%20обмен/Служебный%20обмен.md) (`COMMAND_SYSTEM`)** — периодические пинг-запросы для проверки активности и поддержания сессии связи с сервером.
* **🛡️ [Служебная часть сообщений (Обзор)](Служебная%20часть%20сообщений/Служебная%20часть%20сообщений.md)** — транспортный сервисный оверлей (состояние сети, ПО ККМ, геоданные, регистрация), передаваемый ККМ в каждом запросе в качестве служебных метаданных.
  * [Служебный запрос](Служебная%20часть%20сообщений/Служебный%20запрос.md) (`ServiceRequest`)
  * [Служебный ответ сервера](Служебная%20часть%20сообщений/Служебный%20ответ%20сервера.md) (`ServiceResponse`)
